# Feature map

This file lists what this tree implements today. It is not a plan. It is a standing map. Each implementation updates its own rows here and its file under `.cursor/skills/verify-call-agent/features/`. How to run the CLI is in [README.md](../README.md). Why the call is a six-track reducer is in [design.md](design.md). CloudAgents start at [AGENTS.md](../AGENTS.md). Wave-1 hold: [WAVE1_HOLD_FEATURE_MAP_PLAN.md](WAVE1_HOLD_FEATURE_MAP_PLAN.md). There is no `call-agent-web` map in this repository.

## Status

`shipped` means stub-proven on this tree. CI or pytest exercises it.

`gated` means a live adapter or live CLI verb exists in code and refuses to run without its keys. Telnyx live needs `QUICK_ASK_LIVE=1` plus the Telnyx and OpenAI keys in `.env.example`. Linq live send and `linq register-webhook` need `LINQ_API_TOKEN`. Register also needs `LINQ_WEBHOOK_URL` or `PUBLIC_WEBHOOK_URL`. `README.md` states the Telnyx live path has not been exercised from this repository.

`not shipped` means placeholder, phase 2, or out of scope. The function may exist and raise.

## accounts

The `users` table is the runtime account record Fly reads. Same ledger DB as `dids` (SQLite unless `NEON_DATABASE_URL` is set). Cap model: one shared Treena iMessage bot (`LINQ_FROM_E164`); each account stores the user's own phone. Stripe is billing only. The website POSTs signed checkout/settings payloads to Fly; Fly is the sole writer. Kickoff looks up by inbound phone. The outbound Telnyx caller ID is `users.from_did` (not unique; not the iMessage bot). `BookRequest.user_id` is `users.user_id`. CLI `account upsert --from-did` seeds the Telnyx from-number. Confirm/dial never calls `ledger.provision`. Name is collected on website `/start` and that copy is in settings after signup. Kickoff reads `users.first_name`. Never collected over iMessage. Display name is `first_name` plus `prefs.full_name`. There is no `users.name` column. Fly `POST /accounts/sync` and `GET /accounts/dashboard` are intended routes on `hidden-beacon-080`, not accidental. Dashboard UI stays on Pages (web).

## Design

`docs/design.md` Usage shows `did provision`, `did list`, `quick-ask`, `verify-quick-ask`, `book`, and `verify-book`. Messaging is a sibling port. See [linq.md](linq.md). Prod webhook ingress is the Worker inbox. `verify-webhooks` is the Worker lever. `verify-message` is the MessagingPort lever. `verify-persistence` is the later port lever. It is listed under Durable persistence.

`README.md` states hold queues, packaging, and SMS are out of scope. Closed alpha includes iMessage through MessagingPort in this process and Worker forward on the Linq hook. Restaurant book is shipped in stub. CLI live book still needs both `PUBLIC_BASE_URL` and `PUBLIC_WEBHOOK_URL` set to the same tunnel to the laptop BOOK process; Fly `PUBLIC_BASE_URL` is not that path. Neon and R2 ports are shipped with sqlite and local fallback. Live Neon and R2 stay gated on env.

`docs/design.md` Shape has "Done-state hangup, then drain the goodbye." and "Artifacts are the proof."
