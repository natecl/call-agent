# GPT-Live prompting

Source of truth: [Prompting GPT-Live](https://developers.openai.com/api/docs/guides/live-prompting) on developers.openai.com, plus the Telnyx outbound GPT-Live recipe and OpenAI's Delegation and tools in GPT-Live note. This note records what this tree takes from those pages and where it lands in the code. It does not restate the pages. When the two disagree, the page wins and this note gets fixed.

## Position

The live path talks to `gpt-live-1` over the Live sessions WebSocket (`wss://api.openai.com/v1/live/sessions`) and prompts it the live-prompting way, not the Realtime way. `OPENAI_LIVE_MODEL` defaults to `gpt-live-1` in `config.py` and `.env.example`. The parser in `call_agent/gpt_live.py` unwraps nested `response.event` frames and still rejects top-level Realtime event shapes, so a Realtime-era prompt or event stream fails loud instead of half-working. `serialize_session_start` sends `session.delegation.responses` with `OPENAI_RESPONSES_MODEL`, backend instructions, and two tools. The app owns the bridge, session state, tools, audio, and hangup. GPT-Live owns speech.

16 kHz L16 identity passthrough already matches the Telnyx guide. It is not the silence fix.

## What the guide asks for, and what this tree does

- **Short live prompt.** `build_instructions` and `build_book_instructions` in `call_agent/domain.py` join one string. Line 0 is role plus personality (tone, pace, frustration). Line 1 is the opener (`first_spoken_line` or `first_book_line`). Line 2 is `question.text` or party, time, and constraints. `StubGptLive.start` reads those two indexes. After that come `DONE_STATE_LINE` (do not end the call yourself; delegate so the backend records and ends), the existing product guardrails (never book on quick-ask, never waitlist, two-sentence cap), and a `Delegation policy` block that names `record_task_result` and `end_call` and says the backend records the result and ends the call. `serialize_session_start` sends the string as `session.instructions` inside `session.start`. `tool_choice` stays `auto`. Per-question wording still comes from `QUESTION_TABLE`.
- **Backend prompt.** `build_backend_instructions` is the Responses `instructions` string. It tells the backend to call `record_task_result` then `end_call` in the same turn. Book and ask share the same two tools; `BookRequest` only changes legal `outcome` values and the task brief.
- **Greet with an append.** After `session.started`, `LiveGptLive.speak_first` sends `session.instructions.append` then `session.commentary.append`, both with `delegation_id: None`. Instructions name the exact opener and say speak first, then listen. They do not say `verbatim`. The reducer still emits the `speak_first` effect on `session.started`.
- **Model speech is not verbatim playback.** The guide says so. The `disclosure_first` check in `verify_quick_ask` therefore reads the agent's transcript for "on behalf of", not only the instructions we sent.
- **One exact-wording rule, kept as hygiene.** Exact `CLOSING_LINE` containment still starts hangup drain `via="trail"`. Needle assessors do not create `ConversationTerminal` on a normal call; they classify at hangup-confirm / webhook fallback. Informal goodbye does not start drain.
- **Responses delegation and the tool loop.** `session.start` includes `session.delegation.type=responses`. Nested `response.event` / `response.output_item.done` with `item.type=function_call` is the only place a tool call is recognized. The app returns `response.item.create` `{function_call_output, call_id}` then `response.create` with no body. Client-mode `session.delegation.created` is still answered with thinking plus commentary.
- **Silence continue, still no backchannel or interruption policy.** `SILENCE_CONTINUE_LINE` stays. The 6 s commentary nudge is not the product. A 20 s silence failsafe steers (`session.instructions.append`, `delegation_id: null`) then farewell-hangs up `via="stall"`. Backchannel, interruption, and language rules stay out.
